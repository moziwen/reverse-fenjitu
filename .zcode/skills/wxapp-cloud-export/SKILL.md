# 云开发小程序数据全量导出

## 原理（为什么云开发反而好拿）

云开发的门卫查"你是不是从小程序里面来的"，不查"你有没有万能钥匙"。
PC 微信跑小程序时留有 CDP 调试端口，从小程序**自己的执行环境里**用它已登录的合法身份调
`wx.cloud.database()`——不需要破解任何鉴权，请求形态与小程序自身完全一致。

## 前置

1. `wechat-miniapp-reverse` 已建立 CDP 连接（`ws://127.0.0.1:62000`）
2. 已从解包产物确认：云环境 ID、集合清单、每页条数限制（通常 20 条/页）

## 导出流程

1. **集合清单**：从 appservice 源码里 grep 所有 `database().collection('<name>')`，列全集
2. **count 对账基准**：先取每个集合的 `count()` 作为服务端总数
3. **翻页拉取**：客户端 API 用 `skip/limit` 翻页（单页 ≤20 条），写入 JSON Lines（每行一条文档）
4. **批量导出**：结果挂 `window.__EXPORT.results`，从 evaluate 批量取回
5. **落地**：`collections/<集合名>.jsonl` + `README.md`（集合说明/主键外键关系/条数/大小）
6. **完整性对账**：服务端 count = 导出行数 = 唯一业务 ID 数，三者一致才许标"全量"；
   对不上的重抓（按 level/分片重跑），直到 100% 对齐

## 超大文档处理

单条 >1MB 的文档无法整读：只按主键过滤取本人/目标记录，或做压缩投影
（大对象只留业务字段，原始版与压缩版二选一保留）。

## 风控纪律（硬约束，来自真实警告处罚，不可协商）

> 2026-09 案例：全量分页导出次日收到微信"被投诉并确认违规"警告。
> 警告在身 = 二次违规直接升级（限制功能/禁止登录）。

1. **身份隔离**：专用工作微信号，绝不绑主手机号和支付；**已被警告的账号立即退役**
2. **限速**：请求间隔 3~8 秒随机；**单日配额**（建议 ≤500 条/天），超了停
3. **拆时间**：一次"全量"拆 3~5 天完成，不一口气拉完
4. **只读不写**：脚本里硬性不出现任何写操作（云函数写/集合写）
5. **最小范围**：只抓还原必需的集合；**他人用户数据没有明确必要就不抓**（抓了就是隐私包袱）
6. **落地脱敏**：导出后 openid/baby_id/昵称/手机号等字段进分析阶段前哈希掉
7. **授权前置**：目标是公司/客户授权的小程序时，先书面问一句"能否拉全量做备份"——
   管理后台能看到查询日志，打招呼比任何技术手段都管用

## 出口条件

- [ ] 全部集合三数对账 100% 一致
- [ ] README.md 成文（集合说明/主外键/规模）
- [ ] 敏感字段已脱敏或明确标注
- [ ] 产物可被数据管线（清洗→构建期打包）直接消费
